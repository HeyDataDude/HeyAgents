# Council — Data Model

All models live in `apps/api/app/models/`. Enums are the shared vocabulary
(`app/core/enums.py`, mirrored in `packages/shared/src/enums.ts`).

## Core objects

### Thought (`thoughts`)
The fundamental input unit. **`original_audio_uri` and `raw_transcript` are never overwritten.**
Key fields: `title`, `original_audio_uri`, `audio_duration`, `raw_transcript`, `clean_transcript`,
`summary`, `thought_type`, `importance`, `urgency`, `topics[]`, `entities[]`, `questions[]`,
`ideas[]`, `possible_actions[]`, `routing_suggestions[]`, `source`, `capture_mode`, `status`,
`starred`, `embedding` (pgvector), `meta`.

### Dispatch (`dispatches`)
A routing decision for one thought: `recipient_agent_ids[]`, `default_response_mode`, `status`.

### AgentDispatch (`agent_dispatches`)
**One row per recipient** — the unit the worker executes. `agent_id`, `response_mode`, `status`
(queued/processing/waiting_for_user/completed/failed/cancelled), `started_at`, `completed_at`,
`response_summary`, `output` (the validated Agent Output Contract), `error`, `read`.

### Agent (`agents`)
`name`, `slug`, `description`, `icon`, `accent`, `system_role`, `provider`, `model`,
`letta_agent_id`, `autonomy_level` (0–4), `interruption_policy`, `is_supervisor`, `enabled`,
`routing_keywords`.

### Memory (`memories`)
Three scopes: GLOBAL / AGENT / PROJECT. `category`, `content`, `embedding`, and **provenance**:
`created_by_agent_id`, `originating_thought_id`, `provenance` JSON. Scopes are never casually merged.

### Task (`tasks`)
`title`, `description`, `created_by_agent_id`, `originating_thought_id`, `project_id`, `status`,
`priority`, `due_at`, `requires_user_approval`, `approved`, `rationale` (why it exists).

### Project (`projects`)
`name`, `description`, `status`, `goals[]`, `related_agent_ids[]`, `related_thought_ids[]`,
`related_task_ids[]`.

### ResearchJob (`research_jobs`)
`question`, `agent_id`, `originating_thought_id`, `status`, `progress` (0–100), `sources[]`,
`findings`, `artifact_uri`, `error`.

### Report (`reports`)
`type` (morning/daily/weekly/agent/research/custom), `title`, `range_start/end`, `generated_by`,
`content` (section-based JSON), `related_objects[]`.

### AgentQuestion (`agent_questions`)
`agent_id`, `thought_id`, `question`, `context`, `importance`, `status`, `answer`, `resolved_at`.

### Connection (`connections`)
Cross-agent finding with provenance: `type`, `title`, `explanation`, `confidence`,
`related_objects[]` (type/id/label), `discovered_by`, `dismissed`.

### Job (`jobs`)
Durable background work: `kind`, `status`, `progress`, `payload`, `result`, `error`, `attempts`,
`started_at`, `finished_at`. State lives here (not just Redis) so it survives restarts.

### Activity (`activities`)
Human-readable feed: `kind`, `message`, `actor`, `links[]`, `level`.

### Conversation / Message
Chat & voice sessions. `Conversation` supports single-agent and multi-agent Council calls.

## Provenance

Every derived object references its origin:
`Memory.originating_thought_id`, `Task.originating_thought_id`, `ResearchJob.originating_thought_id`,
`Connection.related_objects[]`, `AgentDispatch.thought_id`. From any object you can navigate back to
the Thought and thereby the original audio — answering *who / why / from which thought / when / which
agent / what context* (spec §49).

## IDs

Prefixed, timestamp-sortable string IDs (`thg_`, `agt_`, `tsk_`, `mem_`, …) via `app/core/ids.py`,
so IDs are recognizable in logs and URLs.

## Migrations

Alembic. The initial migration (`0001_initial`) enables `pgvector` then builds all tables from
`Base.metadata`. Subsequent changes should use incremental autogenerated migrations.
